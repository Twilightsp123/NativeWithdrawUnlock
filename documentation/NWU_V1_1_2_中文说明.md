# Native Withdraw Unlock v1.1.2 — 已验证兼容修复

**日期：2026-10-12。状态：用户已反馈实机成功。** 本说明不代表所有战斗和其他 Mod 组合均已验证。

## 故障

原版 v1.1.0 通过 `bm:register_unit_selection_handler()` 直接占用 CA 的底层单位选择监听器。玩家日志显示 Mod 已加载、开始战斗后仍没有取得 `anchor_unit`，导致原生撤退开关没有被写入。检查玩家提供的 AI Army Control 文件后，发现该 Mod 也会注册同一个底层处理器。**存在可解释日志的竞争机制，但日志没有直接记录哪一次注册覆盖了谁。**

## 修复

- v1.1.2 **完全不再注册底层单位选择处理器**，不再和 AI Army Control 抢占。
- 改用 CA 共享的 `Deployed` 战斗阶段回调；再加一个 500ms 的轻量阶段检查作为备用。
- 真正进入 `Deployed` 后，从玩家联盟的军队、单位及可取得的援军列表中挑选一名通过原有严格验证的单位。
- 搜索失败后至多再重试 8 次（延迟分别是 250、500、1000、2000、4000、8000、15000、30000ms）。成功立即停止搜索；到达上限也停止。
- 不改变 `+0x248`、原生 UID/军队指针双重校验、`mr.uint8(1)` 单字节写入、按钮可见性恢复和成功后 1 秒一次的原生安全维护。

## 发布管理

GitHub `release/native_withdraw_unlock.pack` 与此前提供、用户测试成功的 v1.1.2 候选 Pack **字节完全一致**。为了保持实机测试与发布文件可核对，内部 `VERSION` 仍带有 `candidate` 标记，Pack 内技术说明仍保留候选阶段文字；这是构建历史标记，不表示运行逻辑仍是旧版。新维护状态以本说明及根目录 `CHANGELOG.md` 为准。

不要同时安装新旧版 Pack；需要 Cpecific's Memreader。原 v1.1.0 仍可从 Git 历史提交 `dcd0baf4e410228c4896c4f61df988ca172f6cc1` 还原。
